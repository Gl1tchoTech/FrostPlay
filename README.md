## Initial implementation decisions
- Native SwiftUI app targeting iOS 17+.
- No accounts; library, settings, and recently watched data are stored locally.
- TMDB provides movie/TV metadata and AniList provides anime metadata.
- VidLink is the initial movie/TV playback source; MegaPlay is the initial anime source.
- Anime playback addresses MegaPlay directly by AniList ID (MAL ID as fallback) through its documented `/stream/ani/{anilist-id}/{episode}/{language}` and `/stream/mal/{mal-id}/{episode}/{language}` routes. Playback therefore does not depend on resolving Anikoto's internal catalog ID out of its bounded "recent-anime" feed; Anikoto remains only a last-resort resolver for titles with no external ID.
- VidLink and MegaPlay document embed-based playback, so the first player uses `WKWebView`. A hybrid playback layer is also prepared for direct HLS/MP4 sources through `AVPlayer`.
- Source adapters are isolated behind a shared resolver so source priority and fallback behavior can be changed in Settings.
- Playback sources are separated by title type. Settings stores a default source for anime and a separate default for movies/TV, and the resolver only offers MegaPlay to anime (addressed by AniList/MAL ID) and VidLink/MoviesAPI to TMDB titles, so a TMDB title can never attempt MegaPlay. The source picker on a title writes the default for that title type.
- AniList owns anime display metadata, episode numbering, and episode rows; titles that publish no per-episode title get positional episode numbering instead of an empty list.
- Kitsu (`https://kitsu.io/api/edge`) supplies the per-episode details AniList omits, and it is keyless. AniList still owns the numbering and the MegaPlay playback URLs, so Kitsu can only add: it fills in episode titles, synopses, air dates, and episode artwork, and it publishes `anilist/anime` and `myanimelist/anime` mappings so it is addressed with the IDs FrostPlay already holds (one request resolves an AniList or MAL ID to a Kitsu record). Requests are serialized with a short gap and cached, because Kitsu is community-run and rate-limits. Enrichment is bounded to the first 100 episodes of a title, and the whole feature can be switched off in Settings → Catalog & API.
- Home rotates its catalog on every visit: it picks one of six TMDB feeds (trending today/this week, popular movies/shows, top rated movies/shows) at random, and the rail heading names the feed it landed on. Settings → Catalog & API can pin it back to one feed.
- First loads show shimmering placeholders that mirror the shape of the content they replace: a hero block plus rails on Home, a poster grid on Discover and Search, and episode rows on a detail screen. A placeholder stays up for a configurable minimum (default 1.2 s) so content never flashes in and out; later refreshes resolve as fast as the network allows. Configured in Settings → Appearance → Loading.
- The Library is multi-list. Every install keeps a built-in "My List" that a detail screen's list button targets, and users can create, rename, and delete further lists. Adding to any specific list is offered from the long-press menu on every title surface, and a list's own ＋ button adds titles from your watch history and your other lists.
- A list's detail screen carries its cover (tap to change it), an edit-cover / rename / delete row, and per-title rename and remove actions.
- A list's cover draws one to four of its titles (the first four by default, or titles the user pins), a single pinned title, or a photo chosen from the user's library (downscaled before it is stored). Cover style for new lists, title counts, per-list naming, an "all covers" reset, and delete confirmation live in Lists & covers, reachable from the Library tab's sliders button and from Settings → Appearance.
- A title can be renamed inside one list without changing it anywhere else. The per-list name appears in that list (with the real title shown beneath it), while Home rails, grids, and search keep the title's real name.
- The interface uses a single glass design system (`FrostPlay/Views/Components.swift`): continuous rounded surfaces with a hairline highlight instead of capsule pills or hard squares, an animated segmented control, and glass action rows for Play / My List / Source.
- Every title surface (Home rails, hero, poster grids) supports a long-press menu with View details, Play, Add to list (any list, with checkmarks), and Remove from watch history.
- Title-type filters re-run what is on screen instead of resetting it: switching between All, Movie, TV, and Anime keeps a typed query and re-issues it for the new type, and reloads that type's catalog when the field is empty. A service catalog never contains anime, so Discover says so plainly instead of showing an empty grid.
- Home sections are edited in place on the Home screen: tap the sliders icon, then long-press a rail's drag bar and drop it on another rail to reorder it. The same rail carries ▲/▼ nudges and a − remove button, and hidden sections are added back from the same panel. The Settings > Home sections screen remains as a secondary route.
- Service sorting is driven by the service cards: Home's Browse by Service tiles (and Discover's service menu) select a service and load that service's TMDB watch-provider catalog for the US region, while "All" browses the mixed TMDB/AniList catalog.
- Every service tile and service rail heading shows the service's real logo. Logos are fetched once per launch from TMDB's `/watch/providers/movie` and `/watch/providers/tv` artwork, falling back to a bundled-by-URL logo and then to a monogram.
- The Search and Discover tabs browse a catalog without requiring a typed query: All, Movie, TV, and Anime each load a catalog on tap, and pagination keeps loading pages of 20 as the grid is scrolled. Anime browsing requests a different random AniList page on each visit so it is not always the same 20 popularity-sorted titles.
- TMDB requires a `TMDB_API_KEY` value in the app target's configuration; it must not be hard-coded into source files.
